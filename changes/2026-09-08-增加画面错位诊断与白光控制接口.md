## 问题现象

正点原子 i.MX6ULL、内核 `4.1.15-ge48931b1`、官方 OV5640 和
`mx6s_capture` 链路已经可以出图，但连续运行后仍可能出现：

1. 动态画面撕裂或刷新时短暂绿屏；
2. 画面分为左右两半，左侧内容跑到右侧；
3. 现有日志只能证明采集约 30 fps、显示约 16.5 fps，`drop_size=0`、
   `present_errors=0`，不能证明每一层处理的是同一帧；
4. OV5640 模组可能带白光灯，但应用没有安全的暗光检测和控制抽象。

## 问题分析

1. 采集帧进入 display/encode 前会经过 ring 的内存拷贝，必须记录来源 V4L2 buffer
   和内容指纹，才能区分 DMA 内容、ring 槽位复用和后续处理错误。
2. 显示端的 RGB565 转换会读取带有行跨度约束的 YUYV 源帧，并写入 framebuffer
   后台页；只记录总帧数无法确认源帧、ring 帧和目标页是否对应。
3. `FBIOPAN_DISPLAY` 成功并不等价于实际 `yoffset` 一定正确，framebuffer 的
   `line_length`、虚拟高度、像素 bitfield 或页内容被外部改写都可能造成错位。
4. 芯片支持闪光灯不代表当前 BSP 已暴露控制节点；直接写 `/dev/i2c-*` 或开发板
   `sys-led` 会扩大误操作范围，不能作为通用应用方案。

## 问题根因

本轮不把“左右半幅错位”未经证据归因到某一个组件；此前显示侧存在直接写当前扫描
framebuffer 的风险，采集侧也缺少完整 stride/内容证据。新增诊断链路用于确认异常究竟
发生在采集内容、ring 拷贝、YUYV/RGB565 转换、framebuffer 页覆盖、翻页地址，还是
内核 LCD 控制器侧。`drop_disp` 在采集 30 fps、显示约 16.5 fps 时持续增加是 ring
满导致的正常丢帧，不单独视为画面损坏。

### 关键改动说明

1. 每帧携带 `source_sequence`、V4L2 buffer index、时间戳、`bytesperline`、完整帧长和
   四象限指纹进入两条 ring；旧 `ipcam_ring_append()` 与 `ipcam_ring_try_append()`
   继续可用，避免破坏已有测试和其它生产者。
2. `CAP` 严格保留官方 YUYV 的 `bytesperline == width*2`、
   `sizeimage == bytesperline*height`、`bytesused == sizeimage` 约束。序号跳变、回退和
   时间戳异常首发/节流打印上下文，异常帧不进入消费者。
3. `DISP` 使用源帧元数据中的 `bytesperline` 转换，不再隐含假设每行紧密相邻；
   每次翻页的 DEBUG 日志包含目标页、页地址、请求/实际 `yoffset` 和耗时。每 5 秒
   重新读取完整 framebuffer 布局，发现变化、页地址异常或后台页被改写时报警并停止；
   初始化不再清空可能正在扫描的当前页，避免启动阶段制造一次直接写屏。
4. 白光默认 `auto`，平均 Y 不高于 35 连续 15 帧请求开启，高于 55 连续 30 帧请求关闭，
   两次状态变化至少间隔 3 秒。只接受已查询到的 `V4L2_CID_FLASH_LED_MODE` 或明确
   的 camera/flash/white LED class；无后端时打印 `white light control unavailable`
   并保持关闭。`IPCAM_WHITE_LIGHT=off` 禁用自动控制并先请求安全关灯；退出时即使
   状态机认为灯已关闭也会重发一次 OFF，覆盖启动关灯失败的情况。
5. 保持 `run mybootnet` 后由 NFS `rcS` 自动加载 `mx6s_capture`、`ov5640_camera`
   并启动 `S90ipcam`；不加载旧 IPU 模块，不修改 DTS、U-Boot 或内核。

## 预期结果

1. `run mybootnet` 后串口自动出现 `MAIN/CAP/DISP/LIGHT/ENC` 日志，无需手工执行
   `tail -f /var/log/ipcam.log`；`IPCAM_LOG_LEVEL=5` 时可看到逐次 pan 和四象限指纹。
2. `CAP` 与 `DISP` 能关联同一个 V4L2 sequence、ring sequence、source/ring probe、
   RGB565 probe、framebuffer 页地址和 yoffset。
3. `source_probe != ring_probe`、`fb_page_corrupt`、`fb_layout`、`bad_yoffset`、
   `pan_error` 或 `pan_timeout` 增加时，日志可以直接指出优先检查的层次；所有应用计数
   正常而画面仍错位时，转向 `dmesg`/mxsfb/中断证据。
4. 有安全后端时暗光状态机按阈值控制白光；无后端时只记录亮度和 unavailable，不误点亮
   开发板状态灯。
