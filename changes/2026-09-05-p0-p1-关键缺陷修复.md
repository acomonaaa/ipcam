## 问题现象

静态审查与交叉核对后，发现多处会直接导致联调失败的缺陷：

1. **配置无法持久化**：通过 HTTP `/api/config` 或 `ipcam_param_save()` 写入 [`/etc/ipcam.conf`](../src/core/ipcam_param.h) 后，重启（或重新 `ipcam_param_init`）总是 CRC 校验失败并回退编译期默认值。
2. **MJPEG 编码异常**：全量构建链 libjpeg-turbo 2.1.x 时，编码路径可能压缩失败、崩溃或输出异常 JPEG；`ipcam-display-only` 则掩盖该问题。
3. **HTTP POST 改配置无效**：`curl -d 'jpeg_quality=80' http://127.0.0.1:8080/api/config` 等常见「头+体一次到达」请求，经常超时或返回 `changes:0`，配置未生效；`/api/ota` POST 同类失败。
4. **OTA 升级后必回滚**：板端 BusyBox ash 下，存在 `ipcam.prev` 时健康检查失败，新版本被自动回滚；即便健康成功，`.prev` 也不删除，后续每次启动仍进看门狗。
5. **WiFi 启动逻辑失败**：`wpa_supplicant -B` 导致父进程误判子进程死亡，真实 daemon 成孤儿，`stop` 杀不到。
6. **局域网无法预览**：默认 HTTP 仅绑定 `127.0.0.1`，与 README 中 `http://<board_ip>:8080/` 验证流程矛盾。
7. **display-only 构建脆弱**：`make clean ipcam-display-only` 仍可能编译真 encode 并链接 `-lturbojpeg`。

## 问题分析

1. **CRC**：[`param_crc()`](../src/core/ipcam_param.c) 从 `offsetof(version)` 扫到结构体末尾，**包含 `crc` 字段**。保存时用旧 `crc` 算哈希再写回；加载时用新 `crc` 再算 → 永不匹配。用同等算法本地复现 `match=0`。
2. **TurboJPEG**：2.1.x 签名为 `(handle, planes, width, strides, height, …)`，[`ipcam_encode.c`](../src/services/ipcam_encode.c) 误传 `(…, strides, W, H, …)`；`tjGetErrorStr` 调用方式也不符合 2.1。
3. **POST body**：[`read_http_request`](../src/services/ipcam_stream.c) 在 `\r\n\r\n` 处返回，body 可能已在缓冲内；POST 处理又从 socket 再读 `Content-Length` 字节 → 挂起至 `SO_RCVTIMEO` 后空 body。
4. **看门狗**：[`S90ipcam`](../scripts/rootfs/etc/init.d/S90ipcam) 使用 bash 风格 `/dev/tcp`；BusyBox ash 实测报 `nonexistent directory`。成功路径只删 `.broken` 不删 `.prev`；超时 20s 短于 4G 拨号最长约 30s。
5. **WiFi**：`-B` 二次守护化使 `waitpid(WNOHANG)` 立刻收到退出状态。
6. **bind / Makefile / README**：默认值与文档、目标选择逻辑不一致。

## 问题根因

| 项 | 根因 |
| --- | --- |
| 配置丢失 | CRC 输入区间错误，自包含 `crc` |
| 编码失败 | TurboJPEG API 实参顺序/错误串 API 用错 |
| POST 无效 | 未消费「已读缓冲中的 body 前缀」 |
| OTA 误回滚 | ash 不兼容 `/dev/tcp` + `.prev` 生命周期错误 + 超时过短 |
| WiFi 失败 | 用 `-B` 却按前台子进程模型跟踪 PID |
| 无法远程预览 | `http_bind_local` 默认 1 |
| display-only | `MAKECMDGOALS` 精确匹配 + 未清空 `TJ_LDFLAGS` |

## 修改方案

### 变更文件列表

- [`src/core/ipcam_param.c`](../src/core/ipcam_param.c) — CRC 改为从 `model` 起；默认 `http_bind_local=0`；SSID/PSK/APN 字符过滤
- [`src/services/ipcam_encode.c`](../src/services/ipcam_encode.c) — 纠正 `tjCompressFromYUVPlanes`；`tjGetErrorStr`/`tjGetErrorStr2`；JPEG 过大则 skip
- [`src/services/ipcam_stream.c`](../src/services/ipcam_stream.c) / [`ipcam_stream.h`](../src/services/ipcam_stream.h) — `read_http_body`；客户端 `pthread_detach`
- [`scripts/rootfs/etc/init.d/S90ipcam`](../scripts/rootfs/etc/init.d/S90ipcam) — `wget` 探活；成功删 `.prev`；超时 60s
- [`src/services/ipcam_netwifi.c`](../src/services/ipcam_netwifi.c) — 去掉 `-B`；写 conf 前再过滤
- [`src/services/ipcam_net4g.c`](../src/services/ipcam_net4g.c) — APN 写入 AT 前过滤
- [`Makefile`](../Makefile) — `findstring` 选 stub；display-only 仅 `-pthread`
- [`README.md`](../README.md) — 去掉假 `camctl net`；注明 wget / install 路径 / 默认 bind

### 关键改动说明

1. CRC：`offsetof(ipcam_param_t, model)` 至结构体末尾，头字段与 CRC 自身不参与校验。
2. POST：定位 `\r\n\r\n` 后前缀拷入 body，再 `read` 补齐；不足返回 400。
3. 看门狗：`wget -q -T 2 -O - http://127.0.0.1:$port/healthz`，响应含 `ok` 视为成功。

### 中文注释说明（代码类变更必填）

- [`ipcam_param.c`](../src/core/ipcam_param.c)：`param_crc` 说明为何排除 crc 字段；默认 bind；`string_has_unsafe_chars` 防注入
- [`ipcam_encode.c`](../src/services/ipcam_encode.c)：TurboJPEG 参数顺序与 JPEG 过大 skip / ring 关闭退出
- [`ipcam_stream.c`](../src/services/ipcam_stream.c)：`read_http_body` 组装策略；`pthread_detach` 与 stop 等待
- [`ipcam_netwifi.c`](../src/services/ipcam_netwifi.c)：明文 conf 再过滤；去掉 `-B` 的原因
- [`ipcam_net4g.c`](../src/services/ipcam_net4g.c)：APN 写入 AT 前过滤
- [`S90ipcam`](../scripts/rootfs/etc/init.d/S90ipcam)：文件头与 `probe_healthz` 已用中文说明 BusyBox/`wget`/`.prev` 策略

## 预期结果

1. 改配置并重启后，`/etc/ipcam.conf` 能通过 CRC 加载，字段保持。
2. 正确链接 turbojpeg 2.1 时，`/stream.mjpg` 能出合法 MJPEG。
3. `curl -d 'jpeg_quality=80' http://<ip>:8080/api/config` 返回 `changes>=1`。
4. BusyBox ash 下造 `.prev`：健康成功则删除 `.prev`；4G 慢启动不在 60s 内误杀（正常起来即可）。
5. WiFi start 成功且 stop 能杀掉对应 `wpa_supplicant`。
6. `make CROSS_COMPILE= clean ipcam-display-only` 不依赖 libturbojpeg 即可链接。
7. 默认可通过板 IP:8080 访问（可用配置改回仅本机）。
