## 问题现象

开发板已经能够显示 800×480 的 LVGL 页面，但所有中文标签为空，英文、数字、背景和图标仍可显示。

1. LVGL 显示、触摸和页面创建链路已经正常，问题只集中在中文文本字形。
2. 当前 `lv_conf.h` 的默认字体是 `lv_font_montserrat_14`，它不包含页面使用的 CJK 字形。

## 问题分析

1. 工程已将 `LV_TXT_ENC` 设置为 `LV_TXT_ENC_UTF8`，页面源文件中的中文字符串也是 UTF-8，因此不是源码编码或字符解析配置错误。
2. `ipcam_ui_fonts_t` 已支持 body、small、title、icon 四类字体，但 `ipcam_lvgl_start()` 之前传入的是空配置，所有文本回退到 Montserrat 14。
3. 完整 CJK 字体会增加嵌入式程序体积和运行时内存压力；当前页面只需要有限的中文字符，适合生成静态子集。

## 问题根因

UI 使用了不含中文字形的 Montserrat 14 作为默认字体。LVGL 能够解析 UTF-8 文本，但查找不到对应 glyph 时不会绘制中文，所以表现为界面框架正常、中文区域空白。

### 关键改动说明

1. 使用 LVGL 源码内的 `SourceHanSansSC-Normal.otf` 作为字体源，只提取当前 `src/ui` C 字符串中的非 ASCII 字符，并补入可打印 ASCII 范围。
2. 使用 `lv_font_conv` 生成 4 bpp、无字偶距的 14/16/20 px LVGL C 字库；当前生成的三个目标文件编译后合计约 90 KB。
3. 在 `ipcam_lvgl_start()` 中把 CJK 字库分别绑定到 body、small、title；icon 仍绑定 `LV_FONT_DEFAULT`，确保 `LV_SYMBOL_*` 图标保持可用。
4. 字库静态链接进 `ipcam`，板端不需要访问字体文件，也不需要启用运行时 OTF/TTF 解析。

### 中文注释说明（代码类变更必填）

**中文注释**：在 [`src/services/ipcam_lvgl.c`](../src/services/ipcam_lvgl.c) 说明原先传入空字体配置导致中文缺 glyph、静态链接和图标字体分工；在 [`src/ui/ipcam_ui_fonts.h`](../src/ui/ipcam_ui_fonts.h) 说明生成来源、运行时约束和只读描述符；在 [`scripts/generate_ui_fonts.sh`](../scripts/generate_ui_fonts.sh) 说明字符提取范围、字号选择和嵌入式取舍；同步更新 [`lv_conf.h`](../lv_conf.h)、[`src/ui/ipcam_ui.h`](../src/ui/ipcam_ui.h) 与 [`src/ui/ipcam_ui.c`](../src/ui/ipcam_ui.c) 的字体契约注释。

## 预期结果

1. 重新编译并部署后，P01～P08 页面中的中文标题、标签、按钮和状态文案均应显示。
2. LVGL 图标、英文、数字和 RGB565 显示行为保持不变。
3. 后续新增 UI 中文时，在 Ubuntu 执行 `bash scripts/generate_ui_fonts.sh`，再执行项目交叉编译和 NFS 部署命令即可更新字库。
