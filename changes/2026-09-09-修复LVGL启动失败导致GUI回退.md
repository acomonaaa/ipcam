## 问题现象

开发板通过 `run mybootnet` 从 `192.168.1.253:/home/acomon/linux/nfs/rootfs` 启动后，摄像头、LCD、触摸和 HTTP 服务均已就绪，但 LCD 看不到设计稿 GUI。

串口日志出现：

```text
lvgl start failed; fallback to direct framebuffer writer
```

这表示应用主动绕过 LVGL，继续使用旧的直接 framebuffer 视频写屏路径。

## 问题分析

1. 内核日志确认 NFS 使用了 `v3,proto=tcp` 并成功挂载指定 rootfs；应用日志中的构建时间也与当前部署的 ARM 二进制一致，因此不是加载了错误目录或旧程序。
2. `fb ready: 800x480 bpp=16 line_length=1600`、`capture ready` 和 `touch started` 证明 framebuffer、摄像头和触摸设备已通过初始化；问题发生在这些硬件链路之后的 LVGL 前端初始化阶段。
3. 原 `ipcam_ui_create()` 会在启动时连续创建 P01～P08。任意一个隐藏页面或控件创建失败，都会让整个 UI 创建返回空指针；`ipcam_lvgl_start()` 对显示对象、输入对象和 UI 对象的失败分支又没有分别记录，串口只能看到最终回退，无法定位具体页面。

## 问题根因

GUI 启动依赖八个页面的“一次性全量创建”，并且初始化失败信息被合并成一个无上下文的返回值。这样隐藏页面的单点失败会误伤启动首屏，主流程随后按设计回退到 direct framebuffer writer，所以屏幕只保留视频而没有 GUI。

## 修改方案

### 变更文件列表

- [`src/ui/ipcam_ui.c`](../src/ui/ipcam_ui.c) — 启动只创建 P01；P02～P08 在首次切换时按需创建，失败页面会清理根对象和动作绑定计数。
- [`src/ui/ipcam_ui.h`](../src/ui/ipcam_ui.h) — 更新页面创建与切换接口的按需创建约定。
- [`src/ui/ipcam_ui_components.c`](../src/ui/ipcam_ui_components.c) — 为根对象、面板、标签和按钮分配失败补充控件类别/坐标日志。
- [`src/services/ipcam_lvgl.c`](../src/services/ipcam_lvgl.c) — 为显示、输入、缓冲区、互斥锁和 UI 创建补充分阶段日志。
- [`changes/README.md`](README.md) — 登记本次修复记录。

### 关键改动说明

1. P01 作为启动最低闭环，成功后立即加载，不再被 P02～P08 的隐藏页面分配结果阻断。
2. 用户进入其他页面时由 `ipcam_ui_load_screen()` 触发对应页面创建；页面失败只返回当前动作失败，已经显示的 P01 不被销毁。
3. 页面创建失败会删除局部 LVGL 根对象，并恢复创建前的 action binding 计数，避免反复重试造成固定绑定表耗尽。
4. LVGL 启动过程现在会按 `core -> display -> input -> UI -> thread` 输出结果；组件分配失败时还会记录页面使用的坐标和控件类型。

**中文注释**：在 [`src/ui/ipcam_ui.c`](../src/ui/ipcam_ui.c) 补充按需创建、失败页面清理和绑定计数回退的线程/生命周期约束；在 [`src/ui/ipcam_ui.h`](../src/ui/ipcam_ui.h) 更新公开接口语义；在 [`src/ui/ipcam_ui_components.c`](../src/ui/ipcam_ui_components.c) 和 [`src/services/ipcam_lvgl.c`](../src/services/ipcam_lvgl.c) 补充控件分配及 LVGL 分阶段错误处理的原因说明。
