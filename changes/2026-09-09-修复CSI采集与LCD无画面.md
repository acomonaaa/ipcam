## 问题现象

板端启动后内核已经发现 OV5640、初始化 `mxsfb` 并注册 `/dev/video1 (mx6s-csi)`，
但 LCD 没有画面，`camctl status` 中 `capture_frames`、`capture_fps` 和
`preview_fps` 均为 0。

应用日志显示：

```text
driver did not honor YUYV (negotiated )
capture start failed; keep control/status services alive
```

## 问题分析

1. 板端同时存在 `/dev/video0` 和 `/dev/video1`；前者是 PxP，后者才是
   `mx6s-csi` 摄像头节点。原默认配置固定打开 `/dev/video0`，没有自动选择 CSI。
2. 手工设置 `IPCAM_VIDEO_DEV=/dev/video1` 后，V4L2 格式清单确认驱动支持 YUYV，
   `S_FMT` 也接受了 YUYV，但出厂 4.1.15 `mx6s-csi` 的 `G_FMT` 没有回填
   `pixelformat`，用户态读到的 FourCC 为 0。
3. 原实现把空 FourCC 当作格式协商失败，采集线程未启动；主流程因此不会启动
   `ipcam_display_start()`。`healthz` 仍可为正常，是因为它只检查进程和 ring
   生命周期，不代表已经产生视频帧。

## 问题根因

媒体链路合并后，原有的 CSI 自动发现和旧版 `mx6s-csi` 空 FourCC 兼容逻辑没有保留。
应用既可能选错视频节点，也会将驱动已经按 YUYV 配置成功的 CSI 设备误判为失败。

## 修改方案

### 变更文件列表

- [`config/ipcam_config.h`](../config/ipcam_config.h) — 默认摄像头路径改为空，启用自动发现并保留环境变量覆盖。
- [`src/services/ipcam_capture.c`](../src/services/ipcam_capture.c) — 增加 CSI 节点扫描、能力筛选、FourCC 诊断和旧驱动格式回退。
- [`src/services/ipcam_capture.h`](../src/services/ipcam_capture.h) — 增加设备身份和兼容标记字段说明。

### 关键改动说明

1. 自动模式扫描并排序 `/dev/videoN`，要求节点同时支持 video capture 与 streaming，
   再按 sysfs 名称、V4L2 driver/card 识别 `mx6s-csi`，不会把 PxP 当作摄像头。
2. `IPCAM_VIDEO_DEV` 非空时继续作为显式路径，但仍执行 capability 检查。
3. `S_FMT` 先严格确认驱动接受 YUYV；对已确认的 `mx6s-csi`，仅在 `G_FMT` FourCC
   为 0 时使用 S_FMT 的 YUYV 结果。
4. 对旧驱动返回的空 `bytesperline` 和 `sizeimage` 使用已验证的 S_FMT 布局，并继续
   检查 stride、帧大小和 ring 容量，避免把错误帧交给显示或编码链路。

### 中文注释说明（代码类变更必填）

本次在 [`src/services/ipcam_capture.c`](../src/services/ipcam_capture.c) 补充了自动
节点选择、V4L2 capability 筛选、FourCC 文本诊断、旧版 CSI 驱动兼容范围以及帧容量
安全校验的中文注释；在 [`src/services/ipcam_capture.h`](../src/services/ipcam_capture.h)
补充了设备路径和兼容标记的接口语义说明；在 [`config/ipcam_config.h`](../config/ipcam_config.h)
补充了自动发现与环境变量优先级说明。

## 预期结果

1. 未设置 `IPCAM_VIDEO_DEV` 时自动选择 `/dev/video1 (mx6s-csi)`，跳过 `/dev/video0 (PxP)`。
2. 板端日志出现 `G_FMT returned pixelformat=NONE` 后继续出现 `camera negotiated`、
   `fb ready` 和 `display thread start`。
3. `camctl status` 中 `capture_frames` 大于 0，LCD 能持续显示摄像头画面。
4. 非 CSI 节点返回错误 FourCC 或缺少 streaming capability 时仍安全失败。
