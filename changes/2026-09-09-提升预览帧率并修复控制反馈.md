## 问题现象

在 800×480 LCD 的 `ipcam` 项目中，用户反馈预览帧率仍有提升空间；视频设置页的翻转选项和屏幕设置页的亮度、自动熄屏选项点击后看不到明确反馈，部分设置看起来没有生效。拍照、开始录像在连续操作后逐渐表现为点击无响应。首页和顶部的 SD 卡状态也不能直接进入详情页，缺少空间、设备、文件系统信息和格式化入口。

## 问题分析

1. 首页录像按钮使用 `RECORD_TOGGLE`，事件转换为开始/停止后提前返回，绕过了统一的即时反馈和状态保持分支；主线程每秒才处理一次动作，期间真实状态快照会把乐观状态恢复为旧状态。
2. 拍照动作会等待下一张 JPEG。重复点击会堆积多个同步请求，后续动作需要等待前面的超时或落盘；此前照片错误还复用了录像错误处理，可能把正在录像的状态改成异常。
3. LVGL 动作结果虽由 control 层生成，但此前没有稳定反馈槽和错误文本回传；设置卡片、单选行、翻转开关也没有统一保证父对象是触控命中目标。
4. YUYV 转 RGB565 的热点路径对每个像素重复计算亮度和色度乘法；P03 的 760×368 预览在 i.MX6ULL 上会放大该开销。
5. 存储状态只复用了录像可用空间探测，缺少独立的挂载、设备和文件系统信息，也没有经过设备身份校验的格式化控制契约。

## 问题根因

控制动作缺少“点击即反馈、结果可回传、重复请求受控”的完整生命周期；录像按钮的切换分支还绕过了已有的状态反馈逻辑。显示转换在低频 ARM CPU 上承担了不必要的逐像素算术。SD 卡页面没有把状态查询和破坏性操作抽象为独立服务，导致无法安全地展示设备详情并执行格式化。

## 修改方案

### 变更文件列表

- [`src/ui/ipcam_ui.c`](../src/ui/ipcam_ui.c) — 统一录像切换路径的即时状态和提示；翻转、亮度、熄屏及存储动作显示提交状态。
- [`src/ui/ipcam_ui_components.c`](../src/ui/ipcam_ui_components.c) — 明确卡片、单选行和二态开关的可点击标志。
- [`src/ui/ipcam_ui_screen_home.c`](../src/ui/ipcam_ui_screen_home.c) — 首页及顶部 SD 状态改为完整可点击区域。
- [`src/ui/ipcam_ui_screen_screen.c`](../src/ui/ipcam_ui_screen_screen.c) — 亮度滑块改用 `LV_EVENT_VALUE_CHANGED`，覆盖点击和拖动。
- [`src/ui/ipcam_ui_screen_storage.c`](../src/ui/ipcam_ui_screen_storage.c) — 增加设备、文件系统、挂载点、容量和格式化确认界面。
- [`src/services/ipcam_lvgl.c`](../src/services/ipcam_lvgl.c) — 增加动作反馈槽、同类动作合并、录像请求保持态、拍照忙保护及控制结果回传。
- [`src/services/ipcam_lvgl.h`](../src/services/ipcam_lvgl.h) — 增加待处理录像动作和拍照进行中状态。
- [`src/services/ipcam_display.c`](../src/services/ipcam_display.c) — 为 YUYV 颜色转换增加启动期查表，保留目标尺寸直转和最新帧策略。
- [`src/services/ipcam_control.c`](../src/services/ipcam_control.c) — 接入翻转独立提交、背光二态回退提示和 SD 卡格式化控制。
- [`src/services/ipcam_control.h`](../src/services/ipcam_control.h) — 扩展存储状态字段和格式化命令。
- [`src/services/ipcam_record.c`](../src/services/ipcam_record.c) — 拍照失败只记录照片错误，不再把正在录像的状态改成异常。
- [`src/services/ipcam_storage.c`](../src/services/ipcam_storage.c)、[`src/services/ipcam_storage.h`](../src/services/ipcam_storage.h) — 读取精确挂载信息和空间统计；只允许已挂载的安全块设备执行二次确认后的格式化。
- [`tests/test_ipcam_storage.c`](../tests/test_ipcam_storage.c)、[`Makefile`](../Makefile) — 增加存储路径保护测试并纳入 `make test-host`。

### 关键改动说明

1. 翻转动作拆成 `APPLY_MIRROR` 独立控制命令，点击后立即进入动作队列，不会因其它未验证的视频分辨率档位失败而连带失效；视频预览每帧读取水平、垂直镜像参数。
2. 录像开始/停止在主线程执行前保留 `STARTING`/`STOPPING` 视觉状态；同类动作和拍照请求合并，正在等待照片时拒绝重复请求并提示原因。control 结果的成功或失败文本由 LVGL 线程显示。
3. 背光优先写自动探测到的 sysfs 节点，缺失时使用 `FBIOBLANK` 作为二态回退，并在只支持亮灭时明确提示；自动熄屏选项仍保存并更新 screen 服务。
4. YUYV 转换预先计算亮度、Cb、Cr 的固定项，内层循环只做查表、加法和 RGB565 饱和，减少 i.MX6ULL 上的整数乘法；预览仍按 P01/P02/P03 视口直接生成，非视频页停止转换。
5. SD 卡详情读取 `/proc/mounts`、`statvfs` 和独立挂载设备号；格式化要求挂载点不是根文件系统、设备为 `mmc*`/`sd*`/`hd*` 块设备、文件系统为 vfat/ext4/exfat，并执行卸载、固定工具 `execv` 格式化、重新挂载和结果反馈。录像期间拒绝格式化。

## 预期结果

1. 预览转换减少热点乘法开销；板端仍需以 `实测 fps` 和串口 `display thread exit/frame` 统计确认实际提升，当前不会虚报摄像头未协商到的更高帧率。
2. 点击翻转、亮度、自动熄屏、拍照和录像后立即出现“正在应用/正在保存/请求已提交”等提示；成功或失败后显示 control 返回的明确原因。
3. 拍照失败不再中断正在进行的录像；重复拍照不会无限堆积动作队列。
4. 首页顶部 SD 状态、首页存储卡片和存储页均可点击；存储页显示挂载点、设备、文件系统、总容量、已用和可用空间。格式化必须二次确认，录像期间和非安全设备均拒绝。
5. 已验证：`make test-host` 通过；ARM 交叉编译命令 `make -B CROSS_COMPILE=/usr/local/arm/gcc-linaro-4.9.4-2017.01-x86_64_arm-linux-gnueabihf/bin/arm-linux-gnueabihf- ipcam -j2` 通过。板端连续帧率、翻转、背光节点和 SD 卡格式化仍需开发板启动后验证。
