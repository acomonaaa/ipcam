## 问题现象

开发板使用 800×480 LCD、本地 YUYV 预览和 LVGL UI 时出现以下问题：

1. 中文、数字和英文字母不显示，只有 Montserrat 字体提供的图标可见。
2. 直播预览按从上到下刷新，肉眼可见撕裂，帧率偏低。
3. 正常直播约三分钟后 LCD 黑屏，但采集、编码和网络服务仍在运行。
4. 无法保证板级环境没有预置 `IPCAM_BACKLIGHT_PATH` 时仍能找到背光节点。

## 问题分析

1. CJK 字库此前使用 LVGL 压缩 bitmap；当前 `lv_conf.h` 没有启用运行时压缩解码，字体查找成功但 bitmap 读取为空，因此正文中的 CJK、ASCII 数字和英文一起消失，图标因继续使用 Montserrat 而保留。
2. 单 framebuffer 路径在 LCD 扫描当前页时逐行写入，显示扫描与 CPU 写入竞争导致撕裂。原预览线程还先生成完整 800×480 RGB565，再由 LVGL 复制/缩放到视频窗口，i.MX6ULL 在 396 MHz 时负载过高。
3. 串口日志在三分钟附近出现 `screen preview paused` 和 `screen backlight off after 3 minutes idle`，没有崩溃或内存错误；根因是旧的无提示自动熄屏策略，而不是进程退出。
4. U-Boot/板级信息表明 i.MX6ULL 可用频率高于运行时的 396 MHz，因此启动时可以在 sysfs 存在时尽力切换到 `performance` 并提升到 `cpuinfo_max_freq`。

## 问题根因

字体生成格式与 LVGL 配置不匹配；LCD 使用单页行刷新；视频转换尺寸与实际视频控件不匹配；默认休眠服务在截止时直接关闭背光，没有给用户选择；背光和 CPU 策略依赖固定环境/默认频率。

### 关键改动说明

1. 字库改为未压缩 bitmap，保持 CJK 字体负责正文/数字/英文，Montserrat 继续负责 `LV_SYMBOL_*` 图标；生成结果已检查三个文件均为 `bitmap_format = 0`。
2. 打开 `/dev/fb0` 时尝试设置 `yres_virtual = 2 * yres`，确认 `ypanstep`、页大小和显存容量后进入 `fb_pan/vsync` 模式。LVGL 两个完整页直接映射 framebuffer，前面的 dirty area 只完成 flush，最后一个区域才切页；不支持时回到单页局部拷贝。
3. `ipcam_ui_get_video_viewport()` 返回 P01/P02 `476×268`、P03 `760×368`，设置页等页面返回 `0×0`；display 线程直接按该尺寸缩放 YUYV，并在 descriptor 中使用同样的宽、高和 stride。
4. screen 服务在固定截止点前 10 秒发布提示状态；“继续显示”重启完整计时，“立即休眠”马上暂停本地预览并关闭背光，采集/编码/HTTP/录像不受影响；状态确认与硬件动作串行化，避免超时操作和触摸唤醒交错；唤醒首触摸只恢复屏幕，释放后才交给 GUI。
5. 背光优先使用 `IPCAM_BACKLIGHT_PATH`，否则扫描 `/sys/class/backlight/*/brightness` 并读取对应 `max_brightness`；没有 sysfs 节点时探测并使用 `FBIOBLANK`，非零值用于唤醒。
6. CPU 调优为 best-effort，不支持 cpufreq 或没有写权限只记录警告，不阻塞启动；正常退出会恢复启动前保存的 governor/max 值。

## 预期结果

1. 三种静态 CJK 字库的 `bitmap_format` 均为 0，中文、英文、数字和图标同时可见。
2. 支持双页的 mxsfb 在板端日志中出现 `fb double buffer ready`、`pan=1` 和 `direct-fb-pan`；不支持的设备明确记录兼容回退。
3. P01/P02/P03 只转换对应视频窗口，设置页停止转换，降低 CPU 负载并消除正常路径的撕裂；板端仍需实测约 15 FPS。
4. 休眠提示、自动休眠、继续显示、立即休眠、`timeout=0` 和触摸唤醒符合设计语义；休眠期间网络直播、编码和录像计数继续增长。
5. 已执行 `make test-host` 和 ARM 完整构建；部署后需在板端执行 `run mybootnet`，观察串口并连续运行 P01/P03 至少 60 秒完成硬件验证。
