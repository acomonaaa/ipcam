## 问题现象

在正点原子 i.MX6ULL、内核 `4.1.15-ge48931b1`、NFS rootfs 和官方 OV5640 CSI
链路已经恢复后，板端可看到摄像头画面，但仍出现：

1. `run mybootnet` 后应用虽然运行，串口没有持续的 `MAIN/CAP/DISP/ENC` 日志；
   手工查看 `/var/log/ipcam.log` 也可能为空。
2. 画面变化时撕裂，刷新过程中偶尔出现绿屏。
3. 运行一段时间后画面左右错位或分成两半。
4. 采集线程约 30 fps，而显示线程约 16.5 fps，单页 framebuffer 写入存在扫描竞争。

## 问题分析

1. 当前日志库将结构化日志写入 `stderr`，直接运行 `/usr/bin/ipcam` 时能够输出日志，
   因此日志格式化和刷新逻辑不是主要问题。
2. BusyBox `start-stop-daemon -b` 会在真正后台进程中把标准输入、输出和错误输出
   重定向到 `/dev/null`。外层 shell 的 `>>/var/log/ipcam.log 2>&1` 无法捕获真正
   `ipcam` 进程的 `stderr`。
3. 原显示线程直接把转换结果写入 framebuffer 当前扫描页。软件转换未完成时 LCD
   控制器已经可能读取同一页，半帧被扫描会表现为撕裂、绿屏或左右错位。
4. V4L2 采集端此前虽然校验了总帧大小，但还需要把 `bytesperline`、`sizeimage` 和
   每个 buffer 的 `bytesused` 作为完整布局约束；短帧或带意外 padding 的帧不能进入
   按紧凑 YUYV 行解释的显示路径。

## 问题根因

日志为空的直接根因是 `start-stop-daemon -b` 丢弃了应用的标准错误；自动启动由
NFS `rcS` 调用 `S90ipcam` 解决。LCD 异常的直接根因是显示线程在单一当前扫描页
上边转换边写入，没有完整帧边界保护；采集布局校验不足会放大短帧、padding 或异常
`bytesused` 带来的错位风险。

## 修改方案

### 变更文件列表

- [`src/services/ipcam_display.c`](../src/services/ipcam_display.c) — 增加 framebuffer 双页申请、后台页 RGB565 转换、`FBIOPAN_DISPLAY` 翻页、VSYNC 退化复制和显示统计。
- [`src/services/ipcam_display.h`](../src/services/ipcam_display.h) — 增加页容量、虚拟高度、当前页、翻页模式、VSYNC 和 staging 缓冲状态。
- [`src/services/ipcam_capture.c`](../src/services/ipcam_capture.c) — 严格校验 `bytesperline`、`sizeimage`、`bytesused`，记录布局并统计异常帧。
- [`src/services/ipcam_capture.h`](../src/services/ipcam_capture.h) — 暴露协商后的行跨度和完整帧容量。
- [`scripts/rootfs/etc/init.d/S90ipcam`](../scripts/rootfs/etc/init.d/S90ipcam) — 去掉 `-b`，优先把应用 stdout/stderr 接到 `/dev/console`，不可用时回退日志文件。
- `/home/acomon/linux/nfs/rootfs/etc/init.d/rcS` — 保持 `mx6s_capture`、`ov5640_camera` 加载后自动启动 `S90ipcam`。
- [`README.md`](../README.md) — 更新自动串口日志、双缓冲和帧布局校验说明。
- [`排查记录-摄像头video1未注册.md`](../排查记录-摄像头video1未注册.md) — 追加串口日志、撕裂、绿屏和错位的根因及修正方案。

### 关键改动说明

1. `S90ipcam` 保留 `start-stop-daemon -m` 的真实 PID 管理，但不再使用 `-b`。有可写
   `/dev/console` 时执行 `</dev/null >/dev/console 2>&1`，所以 `run mybootnet` 后
   `rcS` 自动启动的应用日志直接显示在串口；console 不可用时才追加到
   `/var/log/ipcam.log`。
2. display 初始化使用 `line_length * yres` 计算单页容量，申请并重新读取
   `yres_virtual >= 2*yres`。双页模式中，转换目标固定为当前扫描页的另一页，完整
   转换完成后才调用 `FBIOPAN_DISPLAY`；翻页失败会计数并安全停止显示线程。
3. framebuffer 不支持双页时，转换先写入完整 staging 缓冲；每帧尝试
   `FBIO_WAITFORVSYNC` 后再复制到 LCD。若 VSYNC 也不可用，保留最后的可显示退化路径，
   同时只输出一次明确警告。
4. 官方 OV5640 YUYV 采集布局要求 `bytesperline == width*2`、
   `sizeimage == bytesperline*height`、`bytesused == sizeimage`。不满足条件的帧在
   环形缓冲写入前丢弃；异常数量进入 `drop_size`，避免半帧被显示线程解释。

## 预期结果

1. `run mybootnet` 后无需手工输入 `S90ipcam start` 或 `tail -f`，串口自动出现
   `MAIN/CAP/DISP/ENC` 启动日志和每约 5 秒的运行统计。
2. 板端日志显示自动选择 `/dev/video1` 的 `mx6s-csi`，并记录
   `640x480 YUYV`、`bytesperline=1280`、`sizeimage=614400`。
3. framebuffer 日志显示 `pages=2 mode=pageflip-vsync`；不支持时明确显示
   `single-buffer-vsync` 和 VSYNC 警告。
4. 长时间运行时，LCD 不再因应用直接改写当前扫描页而出现明显撕裂、绿屏和左右错位；
   异常布局帧不会进入两个消费环形缓冲。
5. 摄像头缺失、framebuffer 不支持双页或 V4L2 帧大小异常时，应用输出诊断并安全退出，
   不加载旧 IPU 模块，也不触发内核 oops。

- 静态检查确认实际启动命令不再使用 `start-stop-daemon` 的 `-b`，也没有
  `/dev/video0` 硬编码；NFS `rcS` 仍只加载正确 CSI 模块并自动调用 `S90ipcam start`。
- 板端双缓冲效果、串口自动日志以及长时间 LCD 画面质量：待用户重启并执行
